EMULATOR ARCHITECTURE & METHODOLOGY

ReaBoy vs SameBoy & BGB

An objective, engineering-focused comparison of Game Boy (DMG-01) emulation architectures, design trade-offs, and verification methodology.

Emulation Heritage & Context: The Game Boy emulation ecosystem owes an enormous debt to legendary projects like SameBoy (by LIJI32) and BGB (by beware). Their decades of hardware reverse engineering and accuracy testing represent the gold standard of Game Boy research. ReaBoy does not seek to displace these monumental achievements. Rather, ReaBoy was engineered to fulfill a distinct architectural mission: providing an accessible, zero-dependency native Windows x64 DMG-01 emulator with clean reverse-engineered C# architecture, bundled open-source Bootix firmware, and published automated test telemetry.

Why Choose ReaBoy?

  • Zero Setup Overhead: Download the ZIP, extract anywhere, and drag-and-drop your ROM. No installation wizards, no administrator privileges required.
  • No BIOS Search: Bundled with CC0-licensed Bootix DMG v1.2 firmware out of the box.
  • Pure 1989 Hardware Purism: Focused purely on authentic original DMG-01 monochrome gameplay without convoluted multi-system menus.
  • Clean Educational C# Architecture: Engineered with modern C# and published transparently for researchers and emulation enthusiasts.

When to Use SameBoy

  • Game Boy Color (CGB) Games: If you need full support for Game Boy Color titles with dual-speed CPU, CGB palettes, and HDMA transfers.
  • Cross-Platform Development: First-class native support on macOS, Linux, and libretro frontends.
  • Advanced Debugging: Features instruction-level breakpoints, memory inspection, and VRAM tile viewer.
  • Official Site: sameboy.github.io ↗

When to Use BGB

  • Homebrew Production: BGB is universally revered as the benchmark tool for developing new Game Boy software.
  • Exhaustive Hardware Profiler: Trace execution cycles, inspect register state, and benchmark instruction timings.
  • Link Cable Emulation: Excellent TCP/IP and local link cable multiplayer emulation support.
  • Official Site: bgb.bircd.org ↗

Verification Methodology & Transparency

To ensure reliable, regression-free emulation, ReaBoy employs a dual-stage automated verification pipeline:

1. Headless 240-Frame ROM Test Suite

Every commercial ROM in the 1,592-title library is executed headlessly for 240 frames ($0000 through $0100 handover and early gameplay loop). Memory bus reads, opcode traps, and timer ticks are evaluated to ensure execution stability without uncaught CPU exceptions.

2. 59 Automated Desktop UI Checks

The desktop frontend undergoes 59 automated integration tests covering ROM drag & drop, WinMM audio buffer initialization, keyboard input dispatch, LCD-off STAT Mode 0 reset (Dr. Mario fix), and atomic battery save serialization.

3. Canonical Accuracy Test ROMs

ReaBoy continuously runs classic test ROMs (including Blargg's CPU instruction tests and timing benchmarks) to identify subtle opcode quirks and verify flag behavior ($0100 register state Z=1, C=1, H=1).
